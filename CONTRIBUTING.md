# Contributing to Devora

Thanks for contributing to Devora.

## Before you start

- Read the project README and understand the area you are changing.
- Check existing issues and pull requests before starting duplicate work.
- Keep secrets, credentials, and local environment files out of commits.

## Development workflow

1. Create a focused branch from `main`.
2. Make a small, reviewable change.
3. Run the relevant build, lint, or test commands.
4. Verify the affected UI or behavior when applicable.
5. Open a pull request with a clear summary and validation notes.

## Pull request guidelines

Use a descriptive title and explain why the change is needed. Include screenshots for meaningful UI changes and call out known limitations or follow-up work. Keep unrelated formatting or refactoring out of focused fixes.
